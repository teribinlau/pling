# 叮一下 · 部署指南

给负责部署的人看（机构的 IT，或者帮机构部署的我们）。**一家机构一套**，装在机构自己的服务器上，数据不出机构。

装完的样子：

```
手机 / 电脑浏览器、电脑客户端
        │ https://pling.example.cn
        ▼
┌─ web（nginx，唯一对外的容器：80 / 443）─────────────────────────┐
│  /            网页版（PWA）        /config.json  运行时配置      │
│  /downloads/  电脑客户端安装包     /api/…        转给下面的网关    │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
        api-gw（Supabase 网关）→ auth 登录 · rest 数据 · realtime 实时同步
                                  · storage 文件 · functions 云函数（微信 / QQ 登录、推送）
                               ▼
                         db（PostgreSQL）     每分钟一次的推送任务也在这里触发
数据都在 /opt/pling/data/：db 数据库、storage 上传的文件、certs 证书、downloads 安装包、backups 备份
```

微信 / QQ / 群机器人的申请步骤单独放在《申请指南》里。

---

## 1. 准备

| 项 | 要求 |
|---|---|
| 服务器 | Linux（Ubuntu 22.04 / 24.04、Debian 12、Alibaba Cloud Linux 3、Rocky / CentOS Stream 9 都行），64 位 x86 或 ARM |
| 配置 | 最低 2 核 4 GB 内存、40 GB SSD；200 人以上或者附件多的，建议 4 核 8 GB、80 GB 以上 |
| 域名 | 一个子域名，比如 `pling.example.cn`，解析（A 记录）到服务器公网 IP |
| **ICP 备案** | 服务器在中国大陆的，域名**必须先完成备案**，否则云厂商会拦截 80 / 443 端口。微信、QQ 登录也要求域名已备案。香港 / 海外服务器不用备案，但大陆访问会慢，而且微信 / QQ 的审核同样要填备案号 |
| 端口 | 云服务器的安全组 / 防火墙放行 **80 和 443**（80 用来申请证书和跳转到 https） |
| 邮箱 | 一个能发信（SMTP）的邮箱，用来发登录验证码，第一个管理员一般用它登录。QQ 邮箱、163 邮箱、企业邮箱都可以，要开通 SMTP 并拿到「授权码」 |
| 可选 | 微信服务号、微信开放平台、QQ 互联、群机器人，见《申请指南》 |

> 内网试用（没有域名和证书）也能装：网址填 `http://服务器IP`，选「先不用 HTTPS」。但微信 / QQ 登录、手机「添加到主屏幕」、电脑客户端都要求 https，只能用邮箱登录和网页版。

## 2. 安装 Docker

已经装过 Docker（`docker compose version` 能输出 v2.x）就跳过。

**Ubuntu / Debian**（用阿里云的 Docker 软件源，国内快）：

```bash
sudo apt-get update && sudo apt-get install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update && sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

Debian 把上面两处 `linux/ubuntu` 换成 `linux/debian`。

**Alibaba Cloud Linux / Rocky / CentOS**：

```bash
sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
```

### 镜像加速（大陆服务器必做）

叮一下用到的镜像都在 Docker Hub，大陆直连很慢或者拉不下来。编辑 `/etc/docker/daemon.json`：

```json
{
  "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
}
```

改完运行 `sudo systemctl restart docker`。镜像地址按服务器选：

- **腾讯云服务器**：`https://mirror.ccs.tencentyun.com`（只在腾讯云内网能用）
- **阿里云服务器**：到「容器镜像服务 → 镜像工具 → 镜像加速器」复制自己的地址（`https://xxxx.mirror.aliyuncs.com`，只在阿里云内能用）
- **其他服务器**：用公开的加速站，比如 `https://docker.1ms.run`、`https://docker.m.daocloud.io`、`https://docker.xuanyuan.me`。这些是第三方服务，随时可能变，可以多填几个；也有付费的专属加速

也可以不改 daemon.json，在 `deploy/.env` 里设 `PLING_REGISTRY=docker.1ms.run/`，只对叮一下生效。

## 3. 安装叮一下

### 3.1 拿到安装包

安装包是 `pling-server-<版本>.tar.gz`，里面有网页、云函数、数据库迁移和部署脚本。大陆服务器下载 GitHub 慢的话，先下载到自己电脑，再传上去：

```bash
# 在自己电脑上
scp pling-server-0.1.0.tar.gz root@服务器IP:/opt/

# 在服务器上
cd /opt && tar -xzf pling-server-0.1.0.tar.gz && mv pling-0.1.0 pling
```

下面都假设装在 `/opt/pling`。

### 3.2 运行安装脚本

```bash
sudo /opt/pling/deploy/scripts/install.sh
```

脚本会问：

1. **网页地址**：`https://pling.example.cn`
2. **机构名**：显示在登录页
3. **证书**：
   - `letsencrypt`：自动申请免费证书，每 12 小时检查续期（需要域名已解析到这台服务器、80 端口外网能访问）
   - `files`：用自己的证书（比如阿里云 / 腾讯云的免费证书，下载 Nginx 格式）。把证书放成 `/opt/pling/data/certs/fullchain.pem`（含中间证书）和 `privkey.pem`
   - `none`：先不用 https

然后它会：生成所有密钥（存在 `deploy/.env`，只有 root 能读）→ 拉镜像（第一次 5–15 分钟）→ 启动 → 建数据库 → 申请证书。

也可以不问，一次给全：

```bash
sudo /opt/pling/deploy/scripts/install.sh --url https://pling.example.cn --org "某某中学" --cert letsencrypt --email it@example.cn --yes
```

安装脚本可以**重复运行**：已有的密钥和配置不会被换掉。改了 `.env` 以后再跑一次也行（或者在 `deploy/` 目录里运行 `docker compose up -d`）。

### 3.3 配邮箱（验证码登录）

编辑 `/opt/pling/deploy/.env`：

```
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=12345678@qq.com
SMTP_PASS=授权码（不是 QQ 密码）
SMTP_ADMIN_EMAIL=12345678@qq.com
SMTP_SENDER_NAME=某某中学 · 叮一下
```

然后在 `deploy/` 目录里运行 `docker compose up -d`。很多云服务器默认封了 25 端口，所以用 465。

### 3.4 第一次登录

**装完马上登录**：第一个登录的人自动成为管理员。打开 `https://pling.example.cn`，用邮箱验证码（或者已经配好的微信 / QQ）登录，然后：

1. **设置 → 机构**：机构名；称呼选「学校 / 学院 / 公司 / 团队」（界面上的「班级 / 部门 / 小组」「全校 / 全公司」跟着变）；时区默认上海
2. **设置 → 节假日**：已经内置 2026 年的放假和调休安排。每年 11 月前后国务院公布下一年的安排，到时候在这里加上
3. **设置 → 成员**：建班级 / 部门
4. **设置 → 邀请码**：给每个班级 / 部门生成邀请码，把链接或二维码发到群里。新成员用邀请码进来，自动激活并进到对应的班级 / 部门。不用邀请码直接登录的人是「待激活」，要管理员在「成员」里手动激活

## 4. 微信 / QQ 登录和推送

按《申请指南》申请好，把 AppID 等填进 `deploy/.env`，再运行 `docker compose up -d`。刷新登录页就会出现对应的按钮：

- **在微信里打开网址**：显示「微信一键登录」（服务号）
- **在电脑上**：显示「微信扫码登录」（开放平台网站应用）
- **QQ 登录**：配好 QQ 互联后，每个地方都显示

**推送**怎么工作：数据库每分钟触发一次云函数 `notify`，它找出该提醒的人和群，然后发：

- **服务号消息**：成员在「设置 → 通知」里扫码绑定服务号。免打扰时间（默认 21:30–07:00，以及周末和法定假日，调休上班的日子照常）里不发，结束后补发
- **群机器人**：管理员在「设置 → 群机器人」里给班级 / 部门配置，可以选「提前提醒 / 到点 / 逾期」哪些阶段发
- 逾期以后最多再催几次，在「设置 → 机构」里设（默认 2 次）

检查推送有没有在跑：

```bash
cd /opt/pling/deploy
docker compose exec db psql -U postgres -c "select jobname, schedule, active from cron.job;"
docker compose exec db psql -U postgres -c "select created_at, channel, stage, status, error from notification_log order by id desc limit 20;"
docker compose logs --tail 50 functions
```

## 5. 电脑客户端

电脑客户端（Windows 64 / 32 位、macOS）是同一套安装包，**每家机构通用**。第一次打开时让用户填服务器地址（`pling.example.cn`），也可以直接粘贴邀请链接。

把安装包放到自己的服务器上，大家从这里下载，以后也从这里自动更新：

```bash
sudo /opt/pling/deploy/scripts/update-desktop.sh 0.1.0
```

脚本从发布地址下载这个版本的安装包和更新清单（`latest.json`），把清单里的下载地址改成你们自己的，放到 `https://pling.example.cn/downloads/`。下载 GitHub 慢的话，先在电脑上下载好再传上去：

```bash
sudo /opt/pling/deploy/scripts/update-desktop.sh --dir /root/pling-desktop-0.1.0
```

目录里要有 `latest.json` 和它列出的所有安装包。

发给大家的下载地址：

- Windows 64 位：`https://pling.example.cn/downloads/Pling_0.1.0_x64-setup.exe`
- Windows 32 位（老电脑）：`https://pling.example.cn/downloads/Pling_0.1.0_x86-setup.exe`
- macOS：`https://pling.example.cn/downloads/Pling_universal.app.tar.gz`

确切的文件名以 `downloads` 目录里的为准。

- Windows 安装包装在当前用户目录，更新不用管理员权限；新版本在后台下载好以后，顶部会提示「重启更新」
- macOS 第一次打开会被拦。去「系统设置 → 隐私与安全性」，拉到底点「仍要打开」
- Windows 7 / 8.1 不能用（系统没有 WebView2）

## 6. 升级

```bash
sudo /opt/pling/deploy/scripts/update.sh 0.2.0
# 或者用已经下载好的安装包
sudo /opt/pling/deploy/scripts/update.sh /root/pling-server-0.2.0.tar.gz
```

升级会先自动备份，然后替换网页、云函数、部署脚本，拉新镜像，执行新的数据库迁移。`deploy/.env` 和 `data/` 不会动。新版本如果多了配置项，脚本会列出来。

下载默认走 GitHub Releases。国内可以把安装包放到自己的对象存储，在 `.env` 里设 `PLING_RELEASE_BASE`（路径格式 `<地址>/v<版本>/<文件名>`）。

## 7. 备份和恢复

### 备份

```bash
sudo /opt/pling/deploy/scripts/backup.sh
```

一份备份是 `data/backups/pling-backup-日期-时间.tar`，里面有：

- 数据库（账号、提醒、讨论、批改记录……）
- 上传的文件
- `.env`（**含密钥，要妥善保管**）

默认保留最近 14 份。建议每天自动备份，并定期把备份拷到别的机器或对象存储：

```bash
sudo crontab -e
# 加一行：每天 3:30 备份
30 3 * * * /opt/pling/deploy/scripts/backup.sh >> /var/log/pling-backup.log 2>&1
```

### 恢复

**同一台服务器**：

```bash
sudo /opt/pling/deploy/scripts/restore.sh /opt/pling/data/backups/pling-backup-20261004-033000.tar
```

会覆盖当前全部数据，要输入「恢复」确认。

**换到新服务器**：

1. 新服务器按第 2、3 节装好 Docker，解开**同一版本或更新版本**的安装包
2. 把备份里的 `env` 复制成新服务器的 `/opt/pling/deploy/.env`：`tar -xf 备份.tar ./env && mv env /opt/pling/deploy/.env`。这样密钥一样，大家不用重新登录
3. 域名解析改到新服务器，运行 `install.sh`
4. 运行 `restore.sh 备份.tar`

恢复只导回数据（表结构由当前版本负责），所以可以把旧版本的备份恢复到新版本，反过来不行。**正式使用前，建议在测试机上演练一遍恢复。**

## 8. 日常运维

都在 `/opt/pling/deploy` 目录里执行：

| 要做什么 | 命令 |
|---|---|
| 看各服务状态 | `docker compose ps` |
| 看日志 | `docker compose logs -f --tail 100 functions`（换成 `web` / `auth` / `db` …） |
| 重启某个服务 | `docker compose restart web` |
| 改了 .env 后生效 | `docker compose up -d` |
| 进数据库 | `docker compose exec db psql -U postgres` |
| 数据库管理后台（可选） | `.env` 里 `COMPOSE_PROFILES` 加上 `studio`，运行 `docker compose up -d`；然后在自己电脑上 `ssh -L 3000:127.0.0.1:3000 root@服务器` 打开 http://localhost:3000 |
| 磁盘占用 | `du -sh /opt/pling/data/*`；Docker 日志每个服务最多 100 MB |
| 停止 / 启动全部 | `docker compose down` / `docker compose up -d`（数据不会丢） |

## 9. 常见问题

**拉镜像失败 / 很慢**：按 2 节配好镜像加速，再运行 `install.sh`。只是个别镜像拉不下来，可以换一个加速地址，或者设 `PLING_REGISTRY`。

**证书申请失败**：

- 检查域名是否已经解析到这台服务器：`ping pling.example.cn`
- 检查 80 端口外网能不能访问（安全组）
- 检查域名有没有备案（大陆服务器）

解决后运行 `deploy/scripts/cert.sh`。在这之前网站是 http，能先用邮箱登录。

**打开网页是空白 / 提示「网页文件缺失」**：

- `docker compose logs web` 看启动脚本的提示
- 检查 `/opt/pling/web/index.html` 在不在
- 用 git 仓库直接部署的，要先 `npm run build`，然后在 `.env` 里设 `PLING_WEB_DIR=../dist`

**登录后一直「待激活」**：正常。管理员在「设置 → 成员」里激活，或者让他用邀请码。

**收不到邮件验证码**：

- `docker compose logs auth | grep -i smtp` 看报错
- 检查 SMTP 密码用的是不是「授权码」，端口是不是 465
- 去垃圾邮件箱找找
- 邮件服务商每天能发的数量有限，人多的机构用企业邮箱

**微信扫码 / 授权页提示「redirect_uri 参数错误」**：

- 开放平台网站应用的「授权回调域」、服务号的「网页授权域名」，要和 `.env` 里 `PLING_PUBLIC_URL` 的域名完全一致（不带 https://）
- 改了以后要等平台生效

**服务号消息收不到**：

| 现象 | 原因和办法 |
|---|---|
| `notification_log` 里错误 40164 | 服务器出口 IP 没加进 IP 白名单 |
| 错误 43004 | 这个人取消关注了服务号；让他重新关注，再在「设置 → 通知」里重新绑定 |
| 错误 47003 | 模板字段对不上，检查 `WECHAT_MP_TEMPLATE_FIELDS` |
| 错误 40037 | 模板 ID 不对 |
| 什么记录都没有 | 先看 `cron.job` 里有没有 `pling-notify`（第 4 节的命令），再看 `docker compose logs functions` |

**群机器人没反应**：

- 在「设置 → 群机器人」点「测试」，看返回的错误
- 钉钉 / 飞书：检查安全设置的密钥和关键词（填「叮一下」）是否一致

**改了服务号 / 微信 / QQ 的配置不生效**：改完 `.env` 要运行 `docker compose up -d`。登录页的按钮要刷新页面才会变。

**手机上一直是旧版本**：网页版有离线缓存，把应用完全关掉再打开一次就会更新。

## 10. 合规提醒

- **个人信息**：叮一下会保存成员的姓名、手机号（选填）、微信 / QQ 的昵称和头像、上传的文件。部署方是数据的处理者，应当告知成员收集了哪些信息、用来做什么，并控制好管理员权限和服务器访问。
- **未成年人**：不满 14 周岁的未成年人的个人信息属于敏感个人信息，依法需要取得监护人同意。面向中小学生使用前，请学校按规定做好告知和同意。
- **中小学作业**：教育部 2021 年《关于加强中小学生手机管理工作的通知》要求「不得用手机布置作业或要求学生利用手机完成作业」，2026 年 7 月的暑期工作通知又作了重申。中小学建议把叮一下用在**教职工之间**（通知、交材料、值班）。作业收交和统计更适合高校、职校、培训机构，或者公司内部收材料。
