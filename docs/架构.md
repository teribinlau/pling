# 叮一下 · Pling — 架构与接口约定

> 从 DZF 提醒 v0.6.2（ff053e4）分出来的通用版：给国内的学校、公司小团队用。**每家客户单独部署一套**，服务器在国内。
> 这份文档是各部分之间的约定（数据库、云函数、配置、部署），改接口时先改这里。

## 1. 已定的决定

| 项 | 决定 |
|---|---|
| 名字 | 叮一下 · Pling（包名 `pling`，桌面应用标识 `de.ilililab.pling`） |
| 交付方式 | 每家客户一套：开源 Supabase 自托管 + 网页，Docker Compose 装在客户的服务器 / 阿里云 / 腾讯云上 |
| 登录 | 微信扫码（开放平台网站应用）、微信内一键登录（服务号网页授权）、QQ（QQ 互联）、邮箱验证码（后备） |
| 推送 | 微信服务号模板消息（成员扫码绑定）+ 企业微信 / 钉钉 / 飞书群机器人（按小组配置）；桌面版本机弹窗照旧 |
| 新功能 | 已读回执、作业统计（收齐率 / 迟交 / 退回重交 / 导出）、邀请码入组、机构设置、国内节假日（含调休） |
| 默认 | 中文界面、Asia/Shanghai、免打扰 21:30–07:00 + 周末和法定假日 |
| 去掉的 | Notion 到柜同步、承运商模板、德语界面、Vercel / Supabase 云 / GitHub 自动更新 |

## 2. 部署结构（一家客户一个域名）

```
https://pling.example.cn/                 网页版（PWA，nginx 静态文件）
https://pling.example.cn/config.json      运行时配置（容器启动时由环境变量生成）
https://pling.example.cn/api/             → Kong（Supabase 网关，去掉 /api 前缀）
    /api/auth/v1/...       GoTrue
    /api/rest/v1/...       PostgREST
    /api/realtime/v1/...   Realtime（WebSocket）
    /api/storage/v1/...    Storage
    /api/functions/v1/...  Edge Functions（云函数）
https://pling.example.cn/downloads/       桌面版安装包 + latest.json（自动更新从这里拉）
https://pling.example.cn/MP_verify_*.txt  服务号「网页授权域名」校验文件（deploy/web-extra/ 里放）
```

- 前端的 `supabaseUrl` = `https://pling.example.cn/api`（supabase-js 支持带路径的地址）
- 微信 / QQ 回调地址 = `https://pling.example.cn/api/functions/v1/auth-callback`（回调域都填 `pling.example.cn`）
- 服务号「服务器配置」URL = `https://pling.example.cn/api/functions/v1/wechat-mp`（明文模式或兼容模式）
- pg_cron 每分钟 → `pling_private.call_notify()` → pg_net POST `http://functions:9000/notify`（内网，带 `x-cron-secret`）

## 3. 运行时配置 `/config.json`

同一份网页 / 桌面安装包可以连任何一家的服务器，所以连接信息不在构建时写死。

```json
{
  "supabaseUrl": "https://pling.example.cn/api",
  "supabaseAnonKey": "eyJ...",
  "publicUrl": "https://pling.example.cn",
  "orgName": "某某中学",
  "logins": { "email": true, "wechat": true, "wechatMp": true, "qq": false },
  "notify": { "wechatMp": true },
  "updatesUrl": "https://pling.example.cn/downloads/latest.json"
}
```

- `logins.wechat` = 配了 `WECHAT_OPEN_APPID`；`logins.wechatMp` / `notify.wechatMp` = 配了 `WECHAT_MP_APPID`；`logins.qq` = 配了 `QQ_APPID`
- 网页版：启动时 `fetch('/config.json')`；没有就退回构建时的 `VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY`；都没有 = 演示模式
- 桌面版：第一次打开让用户填服务器地址（或粘贴邀请链接），取 `<地址>/config.json` 存本机；以后每次启动刷新一次，离线用缓存

关键约定：
- 新用户由 `handle_new_user()` 建 profile：第一个用户 = 管理员 + 激活；其余默认待激活（管理员激活，或用邀请码自己激活）
- 微信 / QQ 新用户：云函数用 GoTrue 管理接口建用户，`email` = 随机的 `u.<uuid>@login.pling.invalid`（GoTrue 要求有个邮箱；不发邮件、不显示，也不从 openid 推出来），`user_metadata = { name: 昵称, avatar_url, login_provider: 'wechat_open' | 'wechat_mp' | 'qq' }`；profile 里 email 存空字符串
- 第三方身份 → 账号的映射只看 `login_identities`：`(provider, openid)` 命中 → 那个账号；没命中按 unionid 找同一家的另一个身份（微信：网站应用 ↔ 服务号；QQ：只和 QQ 比）；登录令牌按 `auth.users.email` 生成（老的邮箱账号加绑后，用微信 / QQ 登录也是它）
- 头像跟着微信 / QQ 更新：只在 profile 头像是空的、或者就是这个身份上次给的头像时才改（用户自己换的不动）；名字只在新建时用昵称，以后不动
- `name_confirmed = false` 的人第一次进应用要先填真实姓名
- 节假日：`kind = 'off'` 的日子「跳过节假日」的提醒不提醒；`kind = 'work'` 的日子「每个工作日」的提醒照样提醒；免打扰的「周末和法定假日」按同一套算

## 6. 云函数（`supabase/functions/<名字>/index.ts`，Deno）

通用约定：
- 每个函数目录：`handler.ts` 导出 `export default async function handler(req: Request): Promise<Response>`；`index.ts` 只有 `Deno.serve(handler)`。测试直接 import handler
- 共享代码放 `supabase/functions/_shared/`；**只用相对路径 + `npm:` 依赖**（国内服务器用 npmmirror 镜像），不用 `jsr:` / `https:` 远程导入
- 数据库：`npm:postgres@3.4.7` 直连 `SUPABASE_DB_URL`（服务端绕过 RLS，所以权限要在函数里自己判断）
- GoTrue 管理接口：`fetch(SUPABASE_URL + '/auth/v1/admin/...')`，头 `apikey` + `Authorization: Bearer <service role>`
- 校验用户身份：`fetch(SUPABASE_URL + '/auth/v1/user', { headers: { apikey, Authorization: 'Bearer <用户的 JWT>' } })`
- 都要处理 CORS（`OPTIONS` 预检；允许 `PLING_PUBLIC_URL`、`tauri://localhost`、`http://tauri.localhost`、开发时的 `http://localhost:1420`）
- 部署时全局关掉网关的 JWT 校验（`FUNCTIONS_VERIFY_JWT=false`），需要登录的函数自己验

共享代码在 `_shared/oauth/`（微信 / QQ 接口、找 / 建账号、`login_requests` 读写、回调结果页）；GoTrue 管理接口在 `_shared/gotrue.ts`。
测试：`tests/functions/auth/`（`deno test -A --config supabase/functions/deno.json tests/functions/auth/`，要先 `scripts/dev-db/up.sh --db pling_auth_test`）。

推送部分（§6.4–6.7）的共享代码：`_shared/wechat-mp.ts`（access_token、模板消息、二维码、消息服务器的验签和 XML）、`_shared/webhooks.ts`（三家机器人的格式、加签、判断成功）、
`_shared/notify/`（`snapshot.ts` 读数据、`plan.ts` 算该发什么、`content.ts` 拼文字、`run.ts` 去重和发送）。
测试：`tests/functions/notify/`（`deno test -A --config supabase/functions/deno.json tests/functions/notify/`，要先 `scripts/dev-db/up.sh --db pling_notify_test`）。
发往微信 / 机器人的每个请求 6 秒超时；错误信息（发送记录、`last_status`、日志）里不带 access_token、机器人地址的参数。

### 6.1 `auth-start`（POST，公开）
请求：`{ provider: 'wechat_open' | 'wechat_mp' | 'qq', client?: 'web' | 'desktop'（默认 web）, returnTo?: string, link?: true }`；
带 `Authorization: Bearer <用户 JWT>` 且 `link: true` = 给当前账号加绑（没带 / JWT 无效 → 401 `unauthorized`；只带 JWT 不带 `link` = 普通登录）。
返回：`{ id, secret, url }` —— `url` 是微信 / QQ 授权页。
- 哪种登录可用看环境变量：wechat_open = `WECHAT_OPEN_APPID` + `WECHAT_OPEN_SECRET`，wechat_mp = `WECHAT_MP_APPID` + `WECHAT_MP_SECRET`，qq = `QQ_APPID` + `QQ_APPKEY`；缺一个 → 400 `provider_disabled`
- `secret`：32 字节随机数的 base64url；库里只存 sha256 十六进制，比较用常数时间。请求 10 分钟有效
- `returnTo` 只接受本站路径：以 `/` 开头、第二个字符不是 `/` 或 `\`，只含可见 ASCII，不含 `#`，最长 1000；否则 400 `invalid_return_to`。不填 / 空串 = 回首页
- 回调地址 `redirect_uri` = `<PLING_FUNCTIONS_URL 或 PLING_PUBLIC_URL/api/functions/v1>/auth-callback`（两个都没配 → 500 `not_configured`）
- `state` = 请求 id 去掉连字符（32 位十六进制；微信要求 state 只用字母数字）。回调里带不带连字符都认
- 授权页（微信对链接做强匹配，参数顺序不能变）：
  - wechat_open：`{OPEN}/connect/qrconnect?appid=…&redirect_uri=…&response_type=code&scope=snsapi_login&state=<id>#wechat_redirect`
  - wechat_mp：`{OPEN}/connect/oauth2/authorize?appid=…&redirect_uri=…&response_type=code&scope=snsapi_userinfo&state=<id>#wechat_redirect`
  - qq：`{QQ}/oauth2.0/authorize?response_type=code&client_id=…&redirect_uri=…&state=<id>&scope=get_user_info`

### 6.2 `auth-callback`（GET，公开，微信 / QQ 跳回来的地址）
`?code=…&state=<id>`：
1. 找 `login_requests`：找不到 → `invalid_request`；发起超过 10 分钟 → `expired`；没有 `code`（用户在微信 / QQ 里点了取消；或带 `error=access_denied`）→ `cancelled`；
   带了别的 `error` 参数 → `wechat_error` / `qq_error`。同一个请求只让一个回调处理（微信内置浏览器偶尔会把回调地址打开两次，code 只能用一次）：
   后到的按先到的结果回应，先到的还没处理完就显示「正在登录」
2. 用 code 换身份（每个接口 10 秒超时）：
   - 微信：`{API}/sns/oauth2/access_token?appid&secret&code&grant_type=authorization_code` → `/sns/userinfo?access_token&openid&lang=zh_CN`。
     出错是 HTTP 200 + `{ errcode, errmsg }` → `wechat_error`；`is_snapshotuser = 1`（朋友圈快照页里的虚拟 openid）→ `wechat_snapshot`，不建账号
   - QQ：`{QQ}/oauth2.0/token?grant_type=authorization_code&client_id&client_secret&code&redirect_uri&fmt=json` → `/oauth2.0/me?access_token&unionid=1&fmt=json` → `/user/get_user_info?access_token&oauth_consumer_key&openid`。
     token / me 出错是 `{ error, error_description }`，get_user_info 出错是 `{ ret ≠ 0, msg }` → `qq_error`（也认 JSONP `callback( {...} );` 格式）
3. 找账号（一个数据库事务，按身份和 unionid 拿 advisory lock，并发的首次登录只建一个用户；`(provider, subject)` 主键再兜底，冲突了以先写进去的为准、删掉多建的 GoTrue 用户）：
   `(provider, openid)` 命中 → 那个账号；否则按 unionid 找同一家的另一个身份（§5）；都没有 → 新建用户（§5，GoTrue 建用户会触发 `handle_new_user()` 建 profile）。
   加绑模式下绑到 `link_user_id`：这个身份（或同一个 unionid）已经属于别的账号 → `already_linked`，什么都不改
4. 服务号登录 / 加绑顺手 upsert `wechat_bindings`（user_id、openid、unionid、nickname，`subscribed` 先写 true —— **不在登录里调服务号的 access_token 接口**；
   没关注的话 notify 发模板消息会收到 43004，再改成 false）；这个 openid 绑在别的账号上 → 挪过来
5. 登录：`POST /auth/v1/admin/generate_link { type: 'magiclink', email }` → 取 `hashed_token` 和 `verification_type`，存进请求，状态 done。加绑不生成令牌
6. 回应：
   - 网页版 302 到 `{PUBLIC}{returnTo ?? '/'}#pling-login=<id>`（加绑成功也是这个）；失败 `#pling-login-error=<代码>`
   - 桌面版（和找不到请求、不知道是谁发起的时候）返回中文 HTML 页：成功「登录成功，可以回到叮一下了，这个页面可以关掉」/ 加绑「绑定成功」；
     失败按代码给中文说明，状态码 400，微信 / QQ 的错误码附在页面上给管理员排查（不含密钥）。页面不带脚本、不缓存、`Referrer-Policy: no-referrer`
7. 错误代码（`#pling-login-error=` 和 auth-finish 的 `error` 用同一套）：
   `invalid_request`、`expired`、`cancelled`、`provider_disabled`（发起之后被关掉了）、`wechat_error`、`wechat_snapshot`、`qq_error`、`already_linked`、`internal`（数据库 / GoTrue 出错）

### 6.3 `auth-finish`（POST，公开）
请求 `{ id, secret }`（缺 / 格式不对 → 400 `invalid_request`）→ 校验 sha256(secret)：
- pending → `{ status: 'pending' }`（桌面版每 2 秒问一次）；回调处理到一半挂了（2 分钟没结果）→ `{ status: 'error', error: 'internal' }`
- done → `{ status: 'done', token_hash, type }`，同时标成 used、清掉库里的令牌（只能取一次，并发的调用只有一个拿得到）；加绑 → `{ status: 'done', linked: true }`（没有令牌，客户端本来就登录着）
- error → `{ status: 'error', error: <代码> }`（可以多次取）
- 不存在 / secret 不对 / 已经取过 / 过期 → 404 `not_found`（几种情况不区分）。过期 = 发起超过 10 分钟；但回调在 10 分钟内开始处理的，开始 / 处理完的 2 分钟内还能取

客户端：`supabase.auth.verifyOtp({ token_hash, type })` 换会话。注意 GoTrue 每个用户只留最新的一个 magiclink 令牌：同一个人几乎同时登录两次，先生成的那个令牌会失效。

### 6.4 `wechat-mp`（服务号消息服务器，公开）
只支持明文模式 / 兼容模式（安全模式只有 `<Encrypt>`、没有明文字段：回 `success`，日志里警告一次）。没配 `WECHAT_MP_TOKEN` = 验签一律不通过。
- GET：验签（sha1(sort(token, timestamp, nonce)) = signature）通过 → 原样返回 `echostr`；不通过 → 403
- POST（XML）：先验签，不通过 → 403。被动回复是文字消息的 XML（字段用 CDATA），不回复时返回 `success`：
  - `subscribe` 且 EventKey = `qrscene_bind_<x>`，或 `SCAN` 且 EventKey = `bind_<x>`（`x` = 20 位 [a-z0-9]）→ 按 `wechat_bind_tickets` 绑定（一个事务，锁住场景值），
    回「已绑定「<姓名>」，以后的提醒会发到这里。在叮一下的「设置 → 通知」里可以随时解绑。」
    - 这个 openid 原来绑在别的账号上 → 挪过来（unionid / 昵称跟着走）；本人换了个微信 → 换成新 openid；`subscribed = true`、`bound_at` 更新、场景值标成用过
    - 场景值不存在 / 过期 / 格式不对 → 回「二维码已过期，请在叮一下的「设置 → 通知」里重新生成。」
    - 已经用过：同一个 openid（微信重发的同一个事件）→ 照样回绑定成功；别的微信 → 回「这个二维码已经用过了…」
  - `unsubscribe` → 这个 openid 的 `subscribed = false`，回 `success`
  - 其他关注（已绑定的人重新关注 → `subscribed` 改回 true，回「欢迎回来」）、`SCAN` 别的码、用户发来的消息（文字 / 图片 / 语音……）→ 回一条带应用链接（`{PUBLIC}/`）的说明
  - 其他事件（菜单、模板消息送达回执、位置上报……）→ `success`
- 微信要求 5 秒内回应：处理超过 4.5 秒就先回 `success`，处理在后台接着做（edge-runtime 里用 `EdgeRuntime.waitUntil`）

### 6.5 `wechat-bind`（POST，要登录：已激活成员）
返回 `{ qrUrl, expiresAt }`：建 `bind_<20 位 [a-z0-9]>` 场景（`wechat_bind_tickets`，10 分钟），调 `/cgi-bin/qrcode/create`（`QR_STR_SCENE`，600 秒），
`qrUrl = https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=<ticket（URL 编码）>`。客户端轮询 / 订阅自己的 `wechat_bindings`。
- 没登录 → 401 `unauthorized`；待激活 → 403 `inactive`；没配服务号（`WECHAT_MP_APPID` / `WECHAT_MP_SECRET` / `WECHAT_MP_TOKEN` 缺一个）→ 400 `wechat_mp_disabled`；
  微信接口出错 → 502 `wechat_error`（`message` 里是微信的错误码和中文说明），场景值删掉

服务号 access_token（`_shared/wechat-mp.ts` 的 `WechatMp`）：
- `POST {API}/cgi-bin/stable_token { grant_type: 'client_credential', appid, secret, force_refresh: false }`，缓存在 `kv_cache`（key `wechat_mp_access_token:<appid>`，提前 5 分钟过期）；
  一次运行里只取一次（并发的请求共用）
- 调接口回 40001 / 40014 / 42001（令牌失效）→ 刷新令牌、重试一次：先用普通模式取（拿到的就是微信那边现在有效的）；拿到的还是被拒的那个，才 `force_refresh: true`
  （会让旧令牌马上失效、每天限 20 次：所有函数加起来一小时最多一次，记在 `kv_cache` 的 `wechat_mp_force_refresh:<appid>`）；一次运行只刷新一次，刷新后还被拒就不再试
- 服务器出口 IP 要加进服务号的「IP 白名单」（不然 40164）

模板消息：`WECHAT_MP_TEMPLATE_ID` 没配 = 不发服务号消息（群机器人照发）。
模板字段映射 `WECHAT_MP_TEMPLATE_FIELDS`（默认 `title=thing1,time=time2,stage=phrase3`）：可用的值 `title`（提醒标题）、`time`（到期时间）、`stage`（即将到期 / 已到期 / 已逾期）、
`team`（指派的小组 → 提醒所属小组 → 「全体」可见的用机构的 `org_label`）、`creator`（创建人）、`note`（备注第一行）；看不懂的项跳过并警告。
按字段名前缀截断（按字符算）：`thing` ≤ 20 字（截掉的最后一位换成「…」）、`phrase` ≤ 5 字、`name` ≤ 10 字（纯英文 ≤ 20）、`character_string` ≤ 32（只留数字字母符号）、`time` 格式 `2026年10月04日 08:30`（机构时区）；空值填「无」（`character_string` 填「-」）。
消息链接 = `{PUBLIC}/?r=<提醒 id>&o=<这一次到期的 ISO 时间>`（打开就是这条提醒的详情）。

### 6.6 `notify`（POST，`x-cron-secret`）
`x-cron-secret` 必须等于非空的 `PLING_CRON_SECRET`（定长比较），否则 401；不是 POST → 405。
`pg_try_advisory_lock` 防止两次运行重叠：拿不到锁 → `{ skipped: 'busy' }`。

每分钟一次。读一份快照（未归档、展开窗口附近的提醒，指派，近 3 天的完成 / 稍后，成员，兼任，小组，节假日，机构设置，通知设置，服务号绑定，启用的群机器人，近 13 小时的发送记录），
先 `setTimeZone(app_settings.timezone)`、`setHolidays(holidays)`，再用 `_shared/core/`（从前端 `src/lib` 同步过来的展开逻辑）展开最近 48 小时到未来（最大提前量）的到期，算：
- **阶段**（和桌面版 `src/lib/scheduler.ts` 一致）：pre（`remind_before_min` > 0，到期前这么多分钟）、due（到点）、overdue#k（到期后每 `overdue_repeat_min` 分钟一次，
  k = 1…`app_settings.push_overdue_max`；桌面版不限次数）。每次到期、每个接收对象只看**已经到点的最晚那个阶段**：12 小时以内、没发过 → 发；更早的不补
- **服务号**：每次到期每个接收人：
  - 接收人：指派的人 + 指派小组的成员（含兼任）；没指派 → 「全体」可见的发给全部成员，其余发给创建人。工位账号、未激活的人都不算
  - 稍后提醒：没到 `until` → 这个人这一次到期什么都不发；`until` 过了 → 多一个阶段 `snooze:<until ISO>`（时间 = until；显示：until 在到期前 = 即将到期，之后 = 已逾期），照样按「最晚的那个」算
  - 不发：已完成（any 模式有人完成 / each 模式本人完成；工位账号代点的按选的名字算）、没绑定 / 取消关注（`subscribed = false`）、关了服务号消息（`notify_prefs.wechat`）、
    在这个人的免打扰里（core 的 `inQuietTime()`，没有 `notify_prefs` 就用 `DEFAULT_NOTIFY_PREFS`：21:30–07:00 + 周末和法定假日，调休上班的日子照发）。
    免打扰里没发的不记录：免打扰结束时还在 12 小时以内，就发那时最晚的阶段
  - 记 `wechat|<user>|<reminder>|<到期 ISO>|<阶段>`；errcode 43004（没关注）→ 这个绑定 `subscribed = false`
  - 拿不到 access_token（IP 白名单、密钥错、微信不通）→ 这次的服务号消息都不发也不记，下一分钟再试（返回里带 `error`）
- **群机器人**：每次到期每个启用的机器人：
  - 归属：指派了小组 → 这些小组的机器人；没指派小组：「全体」可见 → `team_id` 为空的机器人；小组可见 → 提醒所属小组（`reminders.team_id`）的；私人的不发
  - 阶段：算出的「最晚的那个阶段」在机器人的 `stages` 里才发（不另外补发机器人勾了的更早的阶段）；每个阶段最多一次，记 `webhook|<id>|<reminder>|<到期 ISO>|<阶段>`。
    免打扰、稍后提醒、服务号设置都不影响群机器人
  - 名单：each 模式 = 还没完成的人（和应用里作业统计的 `audienceOf()` 一样：指派了 → 接收人；没指派：「全体」= 全部成员，小组可见 = 那个小组的人；都不含创建人），都完成了就不发；
    any 模式：任一人完成就不发，列出直接指派的人（「负责：…」）。机器人属于指派小组之一时，只列 / @ 这个小组的人（each 模式这个组都完成了，这个群就不发）
  - 内容（中文）：
    ```
    【叮一下】交物理实验报告
    时间：10月9日 周五 17:00（已到期）
    还没完成：李四、王五、张三（共 3 人）
    查看：https://pling.example.cn/?r=…&o=…
    ```
    名单按拼音排，超过 40 人写「等」；时间不是今年的带年份。名单里有手机号的人 @ 上（手机号去掉空格 / 横线 / +86，最多 50 个）：企业微信 `text.mentioned_mobile_list`；
    钉钉 `at.atMobiles`，正文末尾也要带 `@手机号`；飞书自定义机器人只能按 open_id @，不 @
  - 钉钉加签：`timestamp`（毫秒）+ `"\n"` + secret 作数据、secret 作 key，HMAC-SHA256 → base64 → URL 上加 `&timestamp=…&sign=<URL 编码>`；
    飞书签名：`timestamp`（秒）+ `"\n"` + secret 作 key，对空串 HMAC-SHA256 → base64，`timestamp`（字符串）和 `sign` 放进 body
  - 成功：企业微信、钉钉 `errcode === 0`；飞书 `code === 0`（老接口 `StatusCode === 0`）；HTTP 出错 / 不是 JSON / 超时都算失败。每次发完更新 `team_webhooks.last_at / last_status`（`ok` 或错误信息）
  - 每个机器人每次运行最多发 15 条（企业微信 / 钉钉每分钟限 20 条），多的不记录、下一分钟接着发
  - 机器人的安全设置用「自定义关键词」时，关键词填「叮一下」（所有消息都以【叮一下】开头，测试消息也是）
- **先记后发**：发之前先插发送记录（`dedupe_key` 唯一，`on conflict do nothing returning`），插不进去 = 别的运行发过了；发失败把这条记录改成 `failed` + 错误信息（不自动重试）。
  中途崩溃最多少发，不会重复发。一个人 / 一个机器人发失败不影响别的；服务号最多 8 条同时发，群机器人另外排队（最多 4 个机器人同时发，同一个机器人的按顺序、间隔 250 毫秒）
- 时间预算 30 秒：超过就不再开始新的发送，剩下的不记录、留给下一分钟（最坏情况 30 + 4 × 6 秒，在 pg_net 的 55 秒超时以内）
- 跑完调 `pling_cleanup()`；返回 `{ sent, failed, skipped, deferred, error? }`（`skipped` = 关了服务号消息 / 免打扰 + 别的运行已经发过；`deferred` = 留给下一分钟的）

### 6.7 `notify-test`（POST，要登录）
返回 `{ ok, error? }`（发没发成功都是 200，`error` 是对方的错误码和说明；请求本身不对才是 4xx）。
- `{ webhookId }`：要管理员（不是 → 403 `admin_only`）。给这个机器人发一条「【叮一下】测试消息：机器人配置成功」（照样加签），同时更新 `team_webhooks.last_at / last_status`；
  没有这个机器人 → 404 `not_found`
- `{ wechat: true }`：任何已激活成员（待激活 → 403 `inactive`），给自己绑定的服务号发一条测试模板消息（链接 `{PUBLIC}/`）；
  没绑定 → 400 `not_bound`；没配模板消息 → 400 `wechat_mp_disabled`；43004 → `subscribed = false`，发成功 → `subscribed` 改回 true
- 没登录 → 401 `unauthorized`；两个都没带 → 400 `bad_request`；不是 JSON → 400 `bad_json`
