# 叮一下 · Pling — 架构与接口约定

> 从 DZF 提醒 v0.6.2（ff053e4）分出来的通用版：给国内的学校、公司小团队用。**每家客户单独部署一套**，服务器在国内。
> 这份文档是各部分之间的约定（数据库、云函数、配置、部署），改接口时先改这里。

## 1. 已定的决定

| 项 | 决定 |
|---|---|
| 名字 | 叮一下 · Pling（包名 `pling`，桌面应用标识 `de.ilililab.pling`） |
| 交付方式 | 每家客户一套：开源 Supabase 自托管 + 网页，Docker Compose 装在客户的服务器 / 阿里云 / 腾讯云上 |
| 登录 | 微信扫码（开放平台网站应用）、微信内一键登录（服务号网页授权）、QQ（QQ 互联）、邮箱验证码（后备） |
| 推送 | 微信服务号模板消息（成员扫码绑定）+ 企业微信 / 钉钉 / 飞书群机器人（按小组配置）；桌面版本机弹窗照旧 |
| 新功能 | 已读回执、作业统计（收齐率 / 迟交 / 退回重交 / 导出）、邀请码入组、机构设置、国内节假日（含调休） |
| 默认 | 中文界面、Asia/Shanghai、免打扰 21:30–07:00 + 周末和法定假日 |
| 去掉的 | Notion 到柜同步、承运商模板、德语界面、Vercel / Supabase 云 / GitHub 自动更新 |

## 2. 部署结构（一家客户一个域名）

```
https://pling.example.cn/                 网页版（PWA，nginx 静态文件）
https://pling.example.cn/config.json      运行时配置（容器启动时由环境变量生成）
https://pling.example.cn/api/             → Kong（Supabase 网关，去掉 /api 前缀）
    /api/auth/v1/...       GoTrue
    /api/rest/v1/...       PostgREST
    /api/realtime/v1/...   Realtime（WebSocket）
    /api/storage/v1/...    Storage
    /api/functions/v1/...  Edge Functions（云函数）
https://pling.example.cn/downloads/       桌面版安装包 + latest.json（自动更新从这里拉）
https://pling.example.cn/MP_verify_*.txt  服务号「网页授权域名」校验文件（deploy/web-extra/ 里放）
```

- 前端的 `supabaseUrl` = `https://pling.example.cn/api`（supabase-js 支持带路径的地址）
- 微信 / QQ 回调地址 = `https://pling.example.cn/api/functions/v1/auth-callback`（回调域都填 `pling.example.cn`）
- 服务号「服务器配置」URL = `https://pling.example.cn/api/functions/v1/wechat-mp`（明文模式或兼容模式）
- pg_cron 每分钟 → `pling_private.call_notify()` → pg_net POST `http://functions:9000/notify`（内网，带 `x-cron-secret`）

## 3. 运行时配置 `/config.json`

同一份网页 / 桌面安装包可以连任何一家的服务器，所以连接信息不在构建时写死。

```json
{
  "supabaseUrl": "https://pling.example.cn/api",
  "supabaseAnonKey": "eyJ...",
  "publicUrl": "https://pling.example.cn",
  "orgName": "某某中学",
  "logins": { "email": true, "wechat": true, "wechatMp": true, "qq": false },
  "notify": { "wechatMp": true },
  "updatesUrl": "https://pling.example.cn/downloads/latest.json"
}
```

- `logins.wechat` = 配了 `WECHAT_OPEN_APPID`；`logins.wechatMp` / `notify.wechatMp` = 配了 `WECHAT_MP_APPID`；`logins.qq` = 配了 `QQ_APPID`
- 网页版：启动时 `fetch('/config.json')`；没有就退回构建时的 `VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY`；都没有 = 演示模式
- 桌面版：第一次打开让用户填服务器地址（或粘贴邀请链接），取 `<地址>/config.json` 存本机；以后每次启动刷新一次，离线用缓存

## 4. 环境变量（`deploy/.env`，云函数都能读到）

| 变量 | 用途 |
|---|---|
| `SUPABASE_URL` | 云函数访问 GoTrue 管理接口用的内网地址（`http://kong:8000`） |
| `SUPABASE_SERVICE_ROLE_KEY` | GoTrue 管理接口（建用户、生成登录令牌） |
| `SUPABASE_DB_URL` | 云函数直连数据库（`postgresql://postgres:…@db:5432/postgres`） |
| `PLING_PUBLIC_URL` | `https://pling.example.cn`（拼回调地址、消息里的链接） |
| `PLING_CRON_SECRET` | notify 的口令（也写进 `pling_private.settings`） |
| `WECHAT_OPEN_APPID` / `WECHAT_OPEN_SECRET` | 开放平台「网站应用」：电脑上扫码登录 |
| `WECHAT_MP_APPID` / `WECHAT_MP_SECRET` | 服务号：微信里一键登录、模板消息、绑定二维码 |
| `WECHAT_MP_TOKEN` | 服务号「服务器配置」里的 Token（验签） |
| `WECHAT_MP_TEMPLATE_ID` | 提醒用的模板 id |
| `WECHAT_MP_TEMPLATE_FIELDS` | 模板字段映射，如 `title=thing1,time=time2,stage=phrase3`（见 §6.5） |
| `QQ_APPID` / `QQ_APPKEY` | QQ 互联网站应用 |
| `WECHAT_API_BASE` / `WECHAT_OPEN_BASE` / `QQ_API_BASE` | 测试时换成假服务器；默认 `https://api.weixin.qq.com` / `https://open.weixin.qq.com` / `https://graph.qq.com` |
| `NPM_CONFIG_REGISTRY` | 云函数下载 `npm:` 依赖用的镜像，国内填 `https://registry.npmmirror.com` |

## 5. 数据库（`supabase/migrations/`，按文件名顺序执行，每个文件重复执行无害）

| 文件 | 内容 |
|---|---|
| 0001–0006 | 继承自 DZF：小组（teams.name 单一名字）、成员、提醒、指派、完成、稍后、回传文件、兼任、附件、讨论 |
| 0007_settings_holidays_invites | `app_settings`（单行：机构名、`team_label`、`org_label`、时区、逾期推送次数）、`holidays`（off / work，含 2026 安排）、profiles 加 `phone / avatar_url / name_confirmed`、新用户触发器、**收紧权限（本人不能改 active / email；待激活的人看不到别人）**、`team_invites` + `redeem_invite(code)` |
| 0008_reads_homework | `reminder_reads`（已读）；submissions 加 `status`（submitted / returned / accepted）、`review_note`、`reviewed_by/at`，创建人 / 管理员能批改；提醒创建人能撤掉别人的完成记录（退回重交） |
| 0009_login | `login_identities`（provider + openid → user_id，unionid 打通）、`login_requests`（一次性登录请求，只有云函数能读写） |
| 0010_notify | `notify_prefs`（服务号开关、免打扰）、`wechat_bindings`（服务号 openid）、`wechat_bind_tickets`、`team_webhooks`、`notification_log`、`kv_cache`、`pling_private.settings` + `call_notify()` + pg_cron 任务、`pling_cleanup()` |

关键约定：
- 新用户由 `handle_new_user()` 建 profile：第一个用户 = 管理员 + 激活；其余默认待激活（管理员激活，或用邀请码自己激活）
- 微信 / QQ 新用户：云函数用 GoTrue 管理接口建用户，`email` = `<provider>.<openid小写>@login.pling.invalid`（只是内部标识，不发邮件、不显示），`user_metadata = { name: 昵称, avatar_url, login_provider: 'wechat_open' | 'wechat_mp' | 'qq' }`；profile 里 email 存空字符串
- `name_confirmed = false` 的人第一次进应用要先填真实姓名
- 节假日：`kind = 'off'` 的日子「跳过节假日」的提醒不提醒；`kind = 'work'` 的日子「每个工作日」的提醒照样提醒；免打扰的「周末和法定假日」按同一套算

## 6. 云函数（`supabase/functions/<名字>/index.ts`，Deno）

通用约定：
- 每个函数目录：`handler.ts` 导出 `export default async function handler(req: Request): Promise<Response>`；`index.ts` 只有 `Deno.serve(handler)`。测试直接 import handler
- 共享代码放 `supabase/functions/_shared/`；**只用相对路径 + `npm:` 依赖**（国内服务器用 npmmirror 镜像），不用 `jsr:` / `https:` 远程导入
- 数据库：`npm:postgres@3.4.7` 直连 `SUPABASE_DB_URL`（服务端绕过 RLS，所以权限要在函数里自己判断）
- GoTrue 管理接口：`fetch(SUPABASE_URL + '/auth/v1/admin/...')`，头 `apikey` + `Authorization: Bearer <service role>`
- 校验用户身份：`fetch(SUPABASE_URL + '/auth/v1/user', { headers: { apikey, Authorization: 'Bearer <用户的 JWT>' } })`
- 都要处理 CORS（`OPTIONS` 预检；允许 `PLING_PUBLIC_URL`、`tauri://localhost`、`http://tauri.localhost`、开发时的 `http://localhost:1420`）
- 部署时全局关掉网关的 JWT 校验（`FUNCTIONS_VERIFY_JWT=false`），需要登录的函数自己验

### 6.1 `auth-start`（POST，公开）
请求：`{ provider: 'wechat_open' | 'wechat_mp' | 'qq', client: 'web' | 'desktop', returnTo?: string }`；
带 `Authorization: Bearer <用户 JWT>` 且 `link: true` = 给当前账号加绑。
返回：`{ id, secret, url }` —— `url` 是微信 / QQ 授权页；没配这个登录方式 → 400 `{ error: 'provider_disabled' }`。
- `returnTo` 只接受以 `/` 开头、不以 `//` 开头的路径
- 授权页：
  - wechat_open：`{OPEN}/connect/qrconnect?appid=…&redirect_uri=…&response_type=code&scope=snsapi_login&state=<id>#wechat_redirect`
  - wechat_mp：`{OPEN}/connect/oauth2/authorize?appid=…&redirect_uri=…&response_type=code&scope=snsapi_userinfo&state=<id>#wechat_redirect`
  - qq：`{QQ}/oauth2.0/authorize?response_type=code&client_id=…&redirect_uri=…&state=<id>&scope=get_user_info`

### 6.2 `auth-callback`（GET，公开，微信 / QQ 跳回来的地址）
`?code=…&state=<id>`：
1. 找 `login_requests`（pending、10 分钟内），用 code 换身份：
   - 微信：`{API}/sns/oauth2/access_token?appid&secret&code&grant_type=authorization_code` → `/sns/userinfo?access_token&openid&lang=zh_CN`
   - QQ：`{QQ}/oauth2.0/token?grant_type=authorization_code&client_id&client_secret&code&redirect_uri&fmt=json` → `/oauth2.0/me?access_token&unionid=1&fmt=json` → `/user/get_user_info?access_token&oauth_consumer_key&openid`
2. 找账号：`(provider, openid)` 命中 → 那个账号；否则微信系按 unionid 找同一个人的另一个微信身份；都没有 → 新建用户（§5）。加绑模式下直接绑到 `link_user_id`（这个身份已经属于别人 → 报错 `already_linked`）
3. 服务号登录的顺手写 `wechat_bindings`（`subscribed` 用 `/cgi-bin/user/info` 查，查不到当 false）
4. `POST /auth/v1/admin/generate_link { type: 'magiclink', email }` → 取 `hashed_token` 和 `verification_type`，存进请求，状态 done
5. 回应：网页版 302 到 `{PUBLIC}/#pling-login=<id>`（失败：`#pling-login-error=<代码>`）；桌面版返回一个中文 HTML 页「登录成功，回到叮一下」
   - 网页版有 `returnTo` 时：`{PUBLIC}{returnTo}#pling-login=<id>`

### 6.3 `auth-finish`（POST，公开）
请求 `{ id, secret }` → 校验 sha256(secret)：
- pending → `{ status: 'pending' }`（桌面版每 2 秒问一次）
- done → `{ status: 'done', token_hash, type }`，同时标成 used（只能取一次）
- error → `{ status: 'error', error }`；不存在 / 过期 / 已用 → 404
客户端：`supabase.auth.verifyOtp({ token_hash, type })` 换会话。

### 6.4 `wechat-mp`（服务号消息服务器，公开）
- GET：验签（sha1(sort(token, timestamp, nonce)) = signature）后原样返回 `echostr`
- POST（XML）：先验签。
  - `subscribe` 且 EventKey = `qrscene_bind_<x>`，或 `SCAN` 且 EventKey = `bind_<x>` → 按 `wechat_bind_tickets` 绑定，回一条文字「已绑定 <姓名>，以后提醒会发到这里」
  - `unsubscribe` → 该 openid 的 `subscribed = false`
  - 其他关注 / 文字消息 → 回一条带应用链接的文字
  - 什么都不回时返回 `success`

### 6.5 `wechat-bind`（POST，要登录）
返回 `{ qrUrl, expiresAt }`：建 `bind_<随机串>` 场景（10 分钟），调 `/cgi-bin/qrcode/create`（`QR_STR_SCENE`，600 秒），
`qrUrl = https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=<ticket>`。客户端轮询 / 订阅自己的 `wechat_bindings`。

服务号 access_token：`POST {API}/cgi-bin/stable_token { grant_type: 'client_credential', appid, secret }`，缓存在 `kv_cache`（提前 5 分钟过期）。
服务器出口 IP 要加进服务号的「IP 白名单」。

模板字段映射 `WECHAT_MP_TEMPLATE_FIELDS`：可用的值 `title`（提醒标题）、`time`（到期时间）、`stage`（即将到期 / 已到期 / 已逾期）、`team`（小组）、`creator`（创建人）、`note`（备注第一行）。
按字段名前缀截断：`thing` ≤ 20 字、`phrase` ≤ 5 字、`name` ≤ 10 字、`character_string` ≤ 32、`time` 格式 `2026年10月04日 08:30`。
消息链接 = `{PUBLIC}/?r=<提醒 id>&o=<这一次到期的 ISO 时间>`（打开就是这条提醒的详情）。

### 6.6 `notify`（POST，`x-cron-secret`）
每分钟一次。读全部数据（未归档提醒、指派、近 3 天的完成、稍后、成员、兼任、小组、节假日、机构设置、通知设置、服务号绑定、群机器人、近 3 天的发送记录），
用 `_shared/core/`（从前端 `src/lib` 同步过来的展开逻辑）算：
- **服务号**：每次到期每个接收人：阶段 pre（提前量 > 0）、due、overdue#k（k = 1…`push_overdue_max`，间隔 `overdue_repeat_min`）。
  取「已经到点且 12 小时内」最晚的那个阶段；没发过、不在这个人的免打扰里 → 发，记 `wechat|<user>|<reminder>|<到期>|<阶段>`。
  - 接收人：指派的人 + 指派小组的成员（含兼任，跳过工位账号和未激活的）；没指派 → 「全体」可见的发给全部成员，其余发给创建人
  - 已完成（any 模式有人完成 / each 模式本人完成）、稍后提醒还没到、没绑定 / 取消关注、关了服务号消息 → 不发
- **群机器人**：每次到期每个机器人：机器人所属小组在这次提醒的指派小组里（没指派小组：「全体」可见 → `team_id` 为空的机器人；小组可见 → 提醒的 `team_id`）；
  阶段只发机器人 `stages` 里勾的；每个阶段最多一次，记 `webhook|<id>|<reminder>|<到期>|<阶段>`
  - 内容：标题、时间、阶段、each 模式列出还没完成的人；有手机号的 @ 上（企业微信 `mentioned_mobile_list`，钉钉 `at.atMobiles`）
  - 钉钉加签：`timestamp + "\n" + secret` HMAC-SHA256 → base64 → 附在 URL；飞书签名：`timestamp + "\n" + secret` 当 key 对空串 HMAC → base64，放进 body
- 跑完调 `pling_cleanup()`；返回 `{ sent, failed, skipped }`

### 6.7 `notify-test`（POST，管理员）
`{ webhookId }` → 给这个机器人发一条测试消息；`{ wechat: true }` → 给自己发一条测试模板消息。返回 `{ ok, error? }`，同时更新 `team_webhooks.last_status`。
